# 2026-09-09

## v0.5.1 —— 修用户实测报的 3 个 bug

用户实测 v0.5.0 后反馈：
1. **窗口缩小/隐藏后卡顿**
2. **还是会出现两个屏幕一起滑动**
3. **还是不能复制文件到另一个屏幕**

### Bug 1+2 共同根因：macOS App Nap（最重要）

- 窗口不可见 → macOS 把进程当 idle → 合并定时器 + 判定 event tap 不活跃 → 送 `TapDisabledByTimeout`。
- tap 被禁用期间：callback 不跑，**本地事件直接进系统**（本地光标动）；tap 重新 arm 后我们仍在 `Forwarding`，又开始 drop+forward → **一鼠双光标**。这就是"卡顿"和"一起滑动"是同一个病。
- **修复**：`capture::disable_app_nap()`，用 `NSProcessInfo beginActivityWithOptions:reason:`（options = `NSActivityUserInitiated | NSActivityIdleSystemSleepDisabled | NSActivityLatencyCritical`），token 存进 `static OnceLock<usize>` 永久持有（**丢了 token = activity 结束 = App Nap 回来**）。必须在 `main()` 建窗口之前调用。
- 项目里**此前完全没有 App Nap 防护**，只有 capture.rs 的注释心虚地提了一句 "or App Nap kicked in"。

### Bug 1+2 第二根因：event-tap 线程里 lock 了 layout

- `return_control()` / `cycle_control()` 都有 `ctx.layout.lock()`，而它俩**都在 event-tap 线程上跑**（tap 被禁用时 callback 调 return_control；hotkey 也在 callback 里检测）。
- 上次会话已经为 `on_capture` 修过这个（改用 `layout_snap`），但这两个函数漏了 → 阻塞 → tap 再次超时 → **恶性循环**，短暂 hiccup 变成持续卡顿。
- **修复**：两个函数都改成 `let snap = c.layout_snap.clone();`。`leave_forwarding` 只用到 `l.local_bbox()`（本地屏包围盒），snap 里有，够用。
- **教训**：凡是能从 event-tap callback 触达的调用链，整条链都禁止 lock `ctx.layout`。加新函数时务必检查。

### Bug 3 根因：剪贴板"文本 vs 文件"两条分支互相打架

- `clipboard.rs` 的 monitor 把 text 和 files 当**两个独立通道**分别比较。
- 但一次粘贴是**一个 pasteboard 状态、多种表示**：Finder 复制文件会同时写 `public.file-url` **和** 纯文本（文件名）。
- 于是死循环：text 分支命中 → `st.files.clear()` → 广播文件名文本；file 分支发现 files "变了" → `st.text = None` → 发文件；下一轮 text 又命中……**每 200ms 交替**。
- 用户看到的现象：远端剪贴板在「文件」和字符串 `"report.pdf"` 之间反复横跳，**粘贴大概率落到文本形式** → 表现为"不能复制文件"。同时机器一直在重编 base64 + 重传 → 也是卡顿来源之一。
- **修复**：一次快照同时读 text + files，**文件优先**；命中文件时把随附的 text 一并记进 `st.text`，让 text 分支无法把它当成新复制。

### Bug 3 第二根因：macOS 只读了一种 pasteboard 表示

- 原来 `read_files()` 只走 `pasteboardItems` + `public.file-url`。只写旧式 `NSFilenamesPboardType` 的 app 复制的文件**完全不可见**。
- **修复**：三级 fallback —— ① `pasteboardItems` 的 `public.file-url` ② pasteboard 上直接的 `stringForType:public.file-url` ③ `propertyListForType:NSFilenamesPboardType`（NSArray<NSString> 绝对路径）。
- `write_files()` 也补写 `NSFilenamesPboardType`，**必须在 `writeObjects:` 之后**（它会 clearContents，写前面会被清掉）。

### 顺带修的两个真实缺陷

- **transfer manifest 与内容不一致**：原来先造 manifest 再开文件，某个文件 `File::open` 失败 → 接收端还在等它的字节 → **后面所有文件内容全错位**。改为先 `open` 全部文件，manifest 只由真正打开成功的生成。
- **`finish()` 不校验**：传输损坏时把不存在的路径写进剪贴板 → Cmd+V 静默失败。现在 `.filter(|p| p.exists())`。
- **`begin()` 误删并发传输**：原来清掉"所有非本次"的目录；改成只清修改时间 > 30min 的。
- **`send_paths` 长时间持 `net` 锁**：整个文件读取+发送期间持有，而 tap callback 也要这把锁 → 传大文件 = 阻塞输入 = tap 超时。改成每条消息单独 lock。
- **`pump_writes` 合并 motion**：把连续 MouseMotion 累加成一帧。位移总量没错，但接收端执行的**光标更新次数变少** → 变成"大步跳"，这正是"远端光标不跟手"。改为**只批量 syscall、不合并内容**。

## v0.5.2 (10:14) — 中英文切换按钮被 macOS 圆角遮挡

**用户反馈**：右上角的中英文切换按钮被遮挡、点不到。"说了好几次了"。

**根因**：`main.rs` 给 eframe 设了 `with_fullsize_content_view(true)`，让内容延伸到原生标题栏下方。这种风格下 TopBottomPanel 的右边缘就是窗口物理右边缘，落到 macOS 圆角 + 红/黄/绿系统按钮所在的"inset 区"里。贴右边的按钮会被圆角吃掉一部分，看起来只剩一条缝。

**修复**（`src/app.rs`）：
1. 把 language toggle 从顶栏完全移走，改放到 sidebar 底部 `Layout::bottom_up` 里 —— 在"退出程序"按钮上方。sidebar 是左侧 232px 的 panel，距窗口右边缘至少 1000px，绝对不会被任何系统 chrome 碰。
2. 新增 `lang_toggle_btn(ui, theme, label) -> bool` 辅助函数，样式和 nav_item 一致（`A文` 小图标 + label，左对齐，30px 高），复用 hover 状态机。toggle_label 仍来自 i18n 的 `toggled_label()`，所以中文态显示"English"、英文态显示"中文"。
3. 顺手把 title bar 的 `inner_margin.right` 从 22 → 34，给 status pill（现在是最右元素）也加上 macOS 圆角安全区，免得未来再加什么右侧控件再被吃。

**教训**：`fullsize_content_view` 下凡是"贴右边"的 UI 都自带风险区。要么留 ≥34px 右 margin，要么干脆不要放在标题栏里。Sidebar / 主内容区是永远安全的。tag v0.5.2 = 671654e，已 push。
