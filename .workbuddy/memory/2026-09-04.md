## 修复 macOS 崩溃（rdev TIS 主线程断言）+ IP 自动探测（v0.3.8）
- 用户报 v0.3.7 打开一会儿就崩溃，且 UI 里 server_addr 一直是写死的 192.168.1.100
- 崩溃根因：rdev 0.5.3 事件 tap 线程（非主线程）调用 TISGetInputSourceProperty，macOS 13+（尤其 26/Tahoe）要求 UI 程序的 Text Input Source API 必须主线程调用 → dispatch_assert_queue_fail → EXC_BREAKPOINT/SIGTRAP。rdev issue #146
- mouseshare 只转发 Key 枚举、从不使用事件的 name 字符字段，所以根本不需要这个键盘布局查询
- 修复方式：将 rdev 0.5.3 vendored 到 vendor/rdev，在 src/macos/keyboard.rs 的 string_from_code 直接返回 None（跳过 TIS 调用）；Cargo.toml 加 `[patch.crates-io] rdev = { path = "vendor/rdev" }`
- IP 修复：main.rs 加载 config 后，若 mode=="primary" 用 local_ip_address::local_ip() 探测本机 LAN IP 写入 server_addr 并 save_config；失败则保留原值
- 提交 ad89da6 `fix: macOS rdev TIS crash + auto-detect LAN IP`，打 tag v0.3.8
- CI 三平台全绿，Release v0.3.8 资产齐全（deb / tar.gz / dmg / Setup.exe / windows.zip）
- 注意：vendor/rdev 是 rdev 0.5.3 的本地副本，若以后升级 rdev 需把补丁同步过去或改用官方已修复版本

## 修复英文版布局溢出 / 蓝色屏幕块贴边（v0.3.10）
- 用户截图反馈：英文版右侧蓝色屏幕块被放得过大、贴到右边缘，顶部 layout_hint 和底部 tip 被截断；中文版留白正常
- 根因：CentralPanel 的 header（标题、hint、图例）依赖 `ui.available_rect_before_wrap()` 计算 canvas 区域；英文 hint 很长，在 `ui.horizontal` 中不换行并溢出，导致后续 cursor 状态异常，canvas 区域被错误放大，屏幕块 scale 变大并覆盖文字
- 修复（src/app.rs）：
  - 把 header 内容显式包进 `ui.vertical(...)`，取返回的 `response.rect` 作为 header 实际高度
  - 用 `ui.max_rect()` 减去 header 高度得到精确的 `canvas_rect`，传给 `draw_layout`
  - `draw_layout` 不再自己调 `ui.available_rect_before_wrap()`，直接画传入的 `canvas_rect`
  - hint 和右上角 tip 改用 `egui::Label::new(...).wrap()` 强制换行，避免英文溢出
- 提交 8bb9fb8 `fix: explicit canvas rect to avoid English layout overflow`，打 tag v0.3.10

## 副机「无连接入口 + 看不到主机屏幕」修复（v0.3.11）
- 用户报：Windows 副机连不上 Mac 主机（地址端口都填对了），且副机界面「没地方连接主机、也没屏幕」
- 根因（两个真实 bug）：
  1. 副机连接只在启动时尝试一次；失败变 `Net::Idle` 只弹静态错误条，左侧 `server_addr` 输入框点「保存」只写文件不重连 → 运行中没有「连接主机」动作入口
  2. 协议无布局同步：副机的 `shared_layout` 只有本地默认那一块屏，主机只在收到 Hello 时把副机加进**自己的**布局，从不把布局回推副机 → 副机画面上没有 Mac 屏
- 修复：
  - protocol.rs 新增 `Message::Layout { layout }`
  - network.rs：`start_hub` 增加 `layout` 参数；`handle_primary_conn` 收到 Hello 先 `ensure_screen` 再立即推送当前布局给该副机；新增 `Net::broadcast_layout`；`connect_client` 增加 `net` 参数，副机断线时把 net 置 `Idle`
  - main.rs：incoming handler 增加 `Message::Layout` 分支（副机覆盖 shared_layout）；`start_hub` 传 `layout`；`connect_client` 传 `net`；`MouseShareApp::new` 传 `inc_tx`
  - app.rs：新增 `inc_tx`/`last_layout_push` 字段；`reconnect()` 方法可热重连并发送 Hello；副机 basic_card 加「连接主机」按钮、startup_error banner 加「重试连接」、status_card 显示连接状态并在 Idle 时显示「重新连接主机」；主机每 2s 节流 `broadcast_layout`
  - i18n 增加 connect_host / retry_connect / reconnect_host / connected / conn_status / conn_primary / conn_connected / conn_idle 中英文案；connect_fail 提示改为「点连接主机重连」
- 提交 37a7279 `fix: secondary connect button + layout sync so host screen shows`，打 tag v0.3.11
- CI 三平台全绿（6 个 check run 均 completed+success），Release v0.3.11 资产齐全
- 注意：最可能的连接失败根因是 macOS 防火墙拦截 49152 入站；代码无法解决，需用户在 Mac 上放行 MouseShare（系统设置→网络→防火墙→允许，或首次运行弹窗点允许）。副机 server_addr 应填 Mac 界面「连接地址」处显示的真实 IP:端口

## 修复「鼠标跨不过去 + Mac 双屏不识别」（v0.3.13 / v0.3.14）
- 用户报：Mac(主机) 连上 Win(副机) 后，Mac 上的鼠标移不到 Win 那台；且 Mac 的两块显示器只识别到一块
- 两个真实根因：
  1. 跨屏失败：`layout::ensure_screen` 把副机放在 `max_x + 40`（留 40px 死区）；`clamp` 在死区里把虚拟光标 snap 回最近屏幕 → 虚拟光标永远到不了副机矩形，跨屏结构性不可能
  2. 多屏不识别：主机布局是 `config.layout` 里写死的一块 1920×1080 屏，没有任何运行时显示器枚举 → Mac 第二块屏从没注册
- 修复：
  - `Screen` 新增 `is_local: bool` 字段（serde default true）：主机的每块物理屏都是 is_local=true（永不被转发），副机屏 is_local=false（接收注入）。用标志位而非「name==primary_name」判断，主机才能拥有多块屏
  - `layout::ensure_screen` 改为「紧贴」放置（ox = max_x，无死区），虚拟光标可连续步进到副机；新增 `local_bbox()` 算本地屏并集包围盒
  - `main.rs detect_primary_layout()`：主机启动用 `display-info`（Core Graphics CGDisplayBounds）枚举真实显示器，按真实坐标摆放每块本机屏；CGDisplayBounds 的全局坐标空间（主屏左上为原点、y 向下）与 rdev 光标坐标一致，所以布局对齐现实。display-info 经 `[target.'cfg(target_os="macos")'.dependencies]` 限定仅 macOS 编译（避免 Win/Linux 拉 windows 0.62 巨无霸，每次发版多 20+ 分钟）
  - `handle_capture` 重写：本地屏不转发；副机屏转发屏内绝对坐标；treadmill 改为基于「本地包围盒」、且只在「该边外侧确有副机屏」时才把真实光标 warp 到本地包围盒对侧（ treadmill 逻辑见 main.rs），让光标持续滚到邻屏
  - app.rs：`draw_layout` 配色改用 `s.is_local`（所有本机屏蓝色★），`is_me` 绿仍保留；补充 Screen 构造处 is_local 字段
