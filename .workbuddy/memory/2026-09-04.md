## 修复 macOS 崩溃（rdev TIS 主线程断言）+ IP 自动探测（v0.3.8）
- 用户报 v0.3.7 打开一会儿就崩溃，且 UI 里 server_addr 一直是写死的 192.168.1.100
- 崩溃根因：rdev 0.5.3 事件 tap 线程（非主线程）调用 TISGetInputSourceProperty，macOS 13+（尤其 26/Tahoe）要求 UI 程序的 Text Input Source API 必须主线程调用 → dispatch_assert_queue_fail → EXC_BREAKPOINT/SIGTRAP。rdev issue #146
- mouseshare 只转发 Key 枚举、从不使用事件的 name 字符字段，所以根本不需要这个键盘布局查询
- 修复方式：将 rdev 0.5.3 vendored 到 vendor/rdev，在 src/macos/keyboard.rs 的 string_from_code 直接返回 None（跳过 TIS 调用）；Cargo.toml 加 `[patch.crates-io] rdev = { path = "vendor/rdev" }`
- IP 修复：main.rs 加载 config 后，若 mode=="primary" 用 local_ip_address::local_ip() 探测本机 LAN IP 写入 server_addr 并 save_config；失败则保留原值
- 提交 ad89da6 `fix: macOS rdev TIS crash + auto-detect LAN IP`，打 tag v0.3.8
- CI 三平台全绿，Release v0.3.8 资产齐全（deb / tar.gz / dmg / Setup.exe / windows.zip）
- 注意：vendor/rdev 是 rdev 0.5.3 的本地副本，若以后升级 rdev 需把补丁同步过去或改用官方已修复版本

## 修复「鼠标跨不过去 + Mac 双屏不识别」（v0.3.13 / v0.3.14）
- 用户报：Mac(主机) 连上 Win(副机) 后，Mac 上的鼠标移不到 Win 那台；且 Mac 的两块显示器只识别到一块

  1. 跨屏失败：`layout::ensure_screen` 把副机放在 `max_x + 40`（留 40px 死区）；`clamp` 在死区里把虚拟光标 snap 回最近屏幕 → 虚拟光标永远到不了副机矩形，跨屏结构性不可能
  2. 多屏不识别：主机布局是 `config.layout` 里写死的一块 1920×1080 屏，没有任何运行时显示器枚举 → Mac 第二块屏从没注册
- 修复：
  - `Screen` 新增 `is_local: bool` 字段（serde default true）：主机的每块物理屏都是 is_local=true（永不被转发），副机屏 is_local=false（接收注入）。用标志位而非「name==primary_name」判断，主机才能拥有多块屏
  - `layout::ensure_screen` 改为「紧贴」放置（ox = max_x，无死区），虚拟光标可连续步进到副机；新增 `local_bbox()` 算本地屏并集包围盒

  - `handle_capture` 重写：本地屏不转发；副机屏转发屏内绝对坐标；treadmill 改为基于「本地包围盒」、且只在「该边外侧确有副机屏」时才把真实光标 warp 到本地包围盒对侧（ treadmill 逻辑见 main.rs），让光标持续滚到邻屏
  - app.rs：`draw_layout` 配色改用 `s.is_local`（所有本机屏蓝色★），`is_me` 绿仍保留；补充 Screen 构造处 is_local 字段

## 修复「双显同动 + 后台失效 + 缺快捷键 + 图标白底」（v0.3.15）

## 控制平面重写 + 后台常驻（v0.3.19，commit 2dd5e9c）
- v0.3.18 实测仍跨不过去 → 找到机制性根因：macOS 把光标钉在屏幕边缘后不再产生移动事件（d=0），所有「边缘+外推位移」判断永远为假
- 双屏同动根因：旧远程模式仅在向外 delta 时回停光标，其他方向光标在 Mac 上自由漂移同时转发
- 关窗即退出的根因：eframe 主窗口关闭 = 进程退出
- main.rs 控制平面重写为两态状态机（Ctrl{remote: Option<RemoteCtrl>}）：
  - 本地模式：永不转发（双动结构上不可能）；钉边检测 + 回弹 12px + 900ms 窗口内累计 2 次推进 → 交接
  - 远程模式：delta 转发为副机屏内绝对坐标，光标漂移>40px 回中锚点；副机内推回共享边缘 → 归还控制
  - 删除 ownership/vcursor/last_real 三把锁，合并为 ctrl 一把（锁序：ctrl→layout→net）
  - 沿边滑动（along 轴 delta>3px）不算推进，防误触发
- app.rs：关闭窗口 → CancelClose + Minimized（后台常驻），状态卡加「退出程序」按钮；布局拖拽立即持久化（主机）
- i18n：background_hint / exit_app 中英文案
- 验证：cargo check 干净；CI 三平台 ×2（tag+main）全 success；Release v0.3.19 五资产齐全
- 教训：跨屏 hand-off 不能依赖贴边后的移动事件（OS 会夹住光标），必须主动回弹制造事件

## 跨屏根因终于定位 + 事件无关触发器（v0.3.23，commit dfb9941）
- 用户质疑"始终无法跨屏，是模型能力问题吗" → 停止盲修，改为实测取证
- 新增 mouseshare --probe 坐标自检：warp 光标到已知布局点，对照 listen 事件流与 CGEventGetLocation 直读
- probe 结果（在本机实测）：坐标系完全对齐（listen == direct == layout bbox），光标能到 bbox 右缘 (3388,416)
- 由此锁定事件路径的机制性死结：光标加速逼近边缘时，最后一个 d>0 事件落在 pin zone 外（x=3385），
  下一个事件已被 OS clamp 到边缘且 d=0，而 d=0 被当作 warp 回声丢弃 → pin 判定永远收不到
  "d>0 且在 pin zone 内"的事件。v0.3.15–22 所有事件驱动交接都因此结构性不可达
- 修复：Edge-rest poller（仅主机）——每 50ms 用 core-graphics CGEventGetLocation 直读光标位置，
  在共享边缘 pin zone 内静止 400ms 即交接（完全不依赖事件 delta）。推住边缘即跨
- 新增 src/diag.rs：mouseshare.log（config 目录旁）记录启动布局 dump、节流光标采样、每次 pin/交接/归还、
  捕获失败——Finder 启动时 stderr 不可见，文件日志是唯一可观测手段；状态卡显示日志路径
- 画布新增橙色实时光标点：点不跟随真实光标 = 坐标错位，一眼可见
- 验证：cargo build 通过；CI 6 检查全 success；Release v0.3.23 五资产齐全
- 附带发现：debug 裸二进制在 winit/icrate 0.0.4 枚举 NSScreen 时 panic（类型码 'q' vs 'Q'），
  仅裸跑触发，release .app 正常（用户一直在用 GUI）
- 方法论教训：GUI/OS 交互 bug 不能只靠读代码猜，第一次就该上 probe/日志取证；本 case 猜了 8 个版本
