## v0.9.0 (18:00) — 五个 bug 一起修：文件复制 / 双光标 / 多机多屏 / 四向拖拽 / 卡顿

用户一次列了五条：
1. mac 端无法向其他端复制文件（之前 windows 可以复制到 mac）
2. mouseshare 缩小隐藏后，鼠标在两个屏幕上同时滑动
3. 要考虑多台电脑、多屏、一台电脑多屏的兼容性
4. 屏幕布局要能上下左右拖拽，实现四向穿越
5. 切屏时偶发卡顿 / 移动不流畅

**一句话根因：整个控制面是按「屏幕」而不是按「机器」路由的。** 布局里每块屏是一个 `Screen`，`predict_cross` 返回 panel 名字，但一台多显示器的副机在布局里是多个 panel——返回谁、从哪块屏的哪条边回来全靠 bbox 猜，于是「多机多屏」和「双光标」其实是同一个 bug 的两张脸。改成 `Screen.host`（机器）+ `RemoteCtrl.panel`（具体显示器）两级，`Hello` 带 `panels: Vec<PanelSpec>` 让副机自报显示器列表，`ensure_host` 负责新机器贴右、老机器重锚。

**（2）双光标：真正原因有两个，一个是 hide 只 hide 了主屏，另一个更阴。** `CGDisplayHideCursor` 只在 app 是前台时生效——最小化后静默 no-op；而且硬件鼠标根本没被摘掉（没调 `CGAssociateMouseAndMouseCursorPosition(false)`），所以副屏上的指针还在被真实鼠标驱动。修法：所有 `active_displays` 都 hide、forwarding 期间 detach、回程时 attach + park。**park 出去的合成事件必须打标**，否则 tap 会把自己的 warp 当成用户输入再转发一次（死循环）——用 `kCGEventSourceUserData`（field 42）写 `SYNTHETIC_MARK`，tap 里过滤掉。还要在 `TapDisabledByUserInput` 时 attach + show，否则系统一暂停捕获就永久卡在「摘掉鼠标」状态。

**（1）文件复制：能查到的证据只有诊断日志，而日志本身有两个盲区。**
- `send_paths` 的「超 512 MB」分支只 `log::warn!`（→ stderr），Finder 启动时 stderr 是丢掉的，所以 `mouseshare.log` 里**一行都没有**。我对着 `mouseshare.log` 数了 7 次 `CLIP-FILES-DETECTED n=1`：4 次后面跟 `FILE-SEND aborted: nothing to send`，3 次后面什么都没有——那 3 次就是超限。所以「静默失败」不是猜的，是数出来的。
- `collect_one` 用 `symlink_metadata` 判断类型，而符号链接自身的 metadata **既不是 dir 也不是 file**，两个分支都不进 → 静默丢弃。只复制一堆软链接时 `collect` 返回空 → 报「nothing to send」。改成 `metadata()`（跟随链接）+ 深度上限防环。
- 目录树遍历**没有任何预算**，复制一个大目录就是「看起来卡死且不写日志」。
- **接收端完全没做路径净化**：`root.join(&entry.path)`，而 `entry.path` 是网络来的字符串。`../../.ssh/authorized_keys` / `/etc/passwd` 直接落盘到 root 之外。加了 `safe_rel()`：丢掉每个 `..`/空段/`C:` 盘符，Windows 上再洗非法字符和保留设备名（`CON.txt` 也是 CON），并且**不删条目只改写**——因为 manifest 的条目数必须和后面 chunk 流的字节账对齐，丢一条就会把后续文件的字节写串。最后再加一道 `dest.starts_with(root)`。
- 空文件（size=0）永远进不了写循环，`File::create` 从来没被调过 → 复制空文件消失。在 `FileEnd` 补建。
- 收端 `write_files` 失败 = 收到但粘不出来，而剪贴板是会被别的进程短暂锁住的资源（Windows 尤其）。加了重试；但只在 `supports_files()` 为真的平台重试——Linux 上 `write_files` 恒假，重试会把**负责转发输入的那条线程**卡 300ms。

**（4）四向拖拽：本机屏幕本来就不该能拖。** 它的位置是系统给的、每次启动重新探测，拖了只会让画布和现实脱钩（连带 edge 几何）。改成 `Sense::hover()` + tooltip 解释。**吸附的真正坑是「只对齐一个轴不够」**：`predict_cross` 要求两块屏在穿越轴上贴合**且**在另一轴上有重叠，只贴合不重叠照样穿不过去——这就是「我拖到右边了还是穿不过去」。所以 snap 分两步：贴合穿越轴 + 另一轴不重叠时拉齐（已重叠就不动，免得跟用户较劲）。`paint_shared_edges` 原来只画左右边，补上下边。

**（5）卡顿：文件块把输入帧饿死了。** 256 KB 的块 + 一次无上限的 `write`，一个 27 MB 的复制就要占住 writer 好几次。块降到 64 KB、writer 按字节预算分批（128 KB/趟）、capture 与 writer 线程抬到 `QOS_CLASS_USER_INTERACTIVE`、发送端每块 yield 1ms。**中途我试过把输入帧提到文件帧前面发，结果三个集成测试挂了**——`EnterScreen` 必须排在解释它的 `MouseMotion` 之前，因果顺序不能为了延迟重排。已回滚，测试恢复。

**踩坑**
- `snap_remote_to_locals` 我第一版**四个方向的贴合方向全写反了**（「在右边」应该把左边缘贴到屏幕右边缘，我写成了右边缘贴过去）。四个方向的单元测试就是拿来抓这个的——几何逻辑不写测试根本看不出来。
