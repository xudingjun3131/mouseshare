**经验**：用户反复说"框子太多"的时候，先看哪些是装饰性的（fill + stroke）、哪些是功能性的（hover bg、active bg）。装饰性的直接砍，功能性的保留——nav_item 的 hover/active 反馈就是这种，没动。card 框完全是装饰。

**遗留**：本次重做保留了 sidebar 的 hairline 右边线（结构性分隔，不是装饰），以及 nav_item 自身的 hover/active 圆角（功能反馈）。下一步如果用户还要更激进，可以再去掉右边线、把 sidebar 改成透明。

## v0.7.2 (15:50) — 修复 traffic lights 与侧栏文字重叠

用户报：mac 的关闭/缩小/最大化三个按钮这一栏和下面的"MouseShare"文字重叠了。

**根因**：窗口用了 `fullsize_content_view(true) + titlebar_shown(false)`，traffic lights 浮在 egui canvas 之上而不是占一条独立 strip。SidePanel top inner margin = 16pt，把"M"文字直接推到 buttons 底下——既重叠也 click-swallow（按钮吃掉文字上半部分的点击）。

**修复**：新加常量 `TITLEBAR_CLEARANCE`（macOS 38pt，其他平台 14pt），应用到 SidePanel top margin。Windows/Linux 是真标题栏所以 14pt 几乎不增加留白；macOS 上 38pt 把品牌块推到 traffic lights 下方且保留了按钮的点击命中。

**自我验证（不再发布前不看图）**：用 `CGWindowListCopyWindowInfo` + `screencapture -l <wid>` 直接对窗口截图，肉眼确认 buttons 和 "MouseShare" 之间有清晰空白。截图工具链记录在 moused-share 的 CGWindowList 模式 — `optionAll` 取所有窗口、过滤 owner=="mouseshare"、用 `bounds.Width>600 && Height>400` 取主窗口、用 `kCGWindowNumber` 拿到 window id 再 `screencapture -o -l` 直截。`disown` 防止后台进程被 shell 终止。

**经验**：fullsize content view 下画在顶部的任何东西都必须算上 traffic light 高度（约 28pt）+ 安全间距，14pt 不够、32pt 是底线、38pt 安全。本项目 macOS 顶栏相关所有 UI 一律用 `TITLEBAR_CLEARANCE` 常量，避免每次重做猜。

CI 三平台全绿、5 个安装包齐全（dmg/Setup.exe/zip/deb/tar.gz）。


## v0.8.0 (16:30) — UI 彻底重做：引入设计系统 src/ui.rs

用户要求：「把这个应用的 UI 彻底重做掉，太丑了。mac，win，ubuntu 都重做掉。」

**根因不是某个控件丑，是没有设计系统。** app.rs 里累积了大量一次性颜色字面量、每个调用点现猜的像素值、以及 `card()/card_header()/card_body()/card_footer()` 这套装饰性框子（v0.7.0 已经把框去掉过一次，但颜色和尺寸仍然散落在各处）。所以这次先建系统，再用系统重画每一页。

- 字号常量：CAPTION 11 / LABEL 12 / BODY 13 / SECTION 14 / METRIC 20 / TITLE 22。
- 文本助手：`measure` / `ellipsize` / `wrap_lines`（按字符走，优先在最后一个空格换行——按空格切词会把中文整段吞掉）。

**app.rs 瘦到 1444 行**（-1628 / +2119，净删约 900 行）。四条页面（连接 / 屏幕布局 / 状态 / 发现的设备）现在只做「组合」，不再出现任何颜色或尺寸字面量。窗口 chrome 重画：SidePanel 用 `TITLEBAR_CLEARANCE` 顶距、内容列居中并封顶 `CONTENT_MAX_W`（两字段表单拉满超宽屏是最容易显得业余的）。

**屏幕 tile 重画成「显示器」**：bezel 渐变（上下各压暗 30%）→ 内嵌屏幕渐变 → 底部 scrim 上写分辨率和名字 → 本机/悬停加 accent 边 → 左上角「本机」徽标。签名 `paint_tile(ui, painter, rect, name, logical, scale, is_primary, is_me, hover, theme, top, bottom, me_label)`。

**状态页「最近事件」接上 `i18n::tr_event`**：原来是把诊断日志原文直接贴出来（机器名、端口、整屏列表混在一行，真正重要的那一行淹在六条相同的启动 banner 底下）。现在 `read_activity(lang, theme, max)` 走 `tr_event`，把日志翻译成人话、按 `Severity` 上色（Ok→green / Info→accent / Warn→orange / Error→red），并且**按消息去重**——同一个事件在日志里会反复出现（每次跨屏、每次捕获重启），八行一样的字对用户毫无信息量。不认识的日志行默认丢弃，除非它报告了错误。

**两个自己撞出来的坑（都是「半透明填充画在什么底上」）**

1. **滚动条变成贴边的发丝线**。egui 的 floating 滚动条默认 `foreground_color = true`，即拿 `widgets.*.fg_stroke.color` 画手柄——而我把 `fg_stroke` 设成了 `theme.text`，于是浅色下是近黑发丝线、深色下是近白发丝线，2pt 宽、紧贴窗口右边，看起来就像一条多余的边框。修法：不碰 `fg_stroke`（文本输入还要用），改 `style.spacing.scroll` —— `bar_width=10`、`floating_width=5`、`bar_outer_margin=3`（floating 也会用它从右边缘内缩）、`handle_min_length=36`、`dormant_handle_opacity=0.0`、`active=0.34`、`interact=0.72`。现在是有内缩、有圆角、低透明度的悬浮胶囊，鼠标不上去就完全不出现（照 macOS overlay scrollbar 的行为）。

2. **启动错误横幅变成近黑色**。横幅用 `theme.red_soft`（13% alpha 的红）当 `TopBottomPanel` 的 fill。它是每帧最早画的东西，底是刚 clear 过的像素（未绘制/透明），不是窗口底色——半透明红在上面合成出来的不是浅粉而是近黑，文字直接看不见。修法：加 `Theme::banner_error` 令牌，用 `mix(window, red, alpha)` **预先合成成不透明色**。规律记下来：**画在卡片上的半透明色没问题；画在面板/窗口级的半透明色必须预合成。**

**验证方式（关键，值得复用）**
- 用 `MS_DEV_PAGE` / `MS_DEV_THEME` 环境变量逐页、逐主题启动截图，四个页面 × 浅色/深色全过一遍。**发布前必须删掉这两个开关**（本次已删，`grep MS_DEV|TEMP-DEV|TEMP-PROBE src/` 无命中）。
- 截图链路：`find.swift` 用 `CGWindowListCopyWindowInfo([.optionAll])` 过滤 `owner=="mouseshare" && Width>600 && Height>400` 拿 `kCGWindowNumber`，再 `screencapture -o -l <id>` 直截窗口（`-o` 去阴影）。`hover.swift` 用 `CGEvent(.mouseMoved)` 悬停。

**其他经验**
