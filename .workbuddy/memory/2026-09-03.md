## mouseshare (cross-platform LAN KVM)
Built from scratch a Rust app that shares mouse/keyboard/clipboard across Win/Linux/Mac over LAN, with a draggable screen-layout GUI.

Stack: `rdev` (capture via `listen` + inject via `simulate`, enable `serialize` feature to forward keys), `arboard` (clipboard), `eframe`/`egui` (GUI), plain TCP length-prefixed JSON protocol.
Topology: one Primary (hub) captures real input and forwards to neighbour screens; Secondaries connect and inject. Edge crossing uses a "treadmill" warp (when cursor hits a screen edge and keeps moving, warp it to the opposite edge so the unbounded virtual cursor continues onto the neighbour).
CI: `.github/workflows/build.yml` builds Win (.exe + Inno Setup), Linux (.deb + tar.gz), Mac (.dmg) and attaches to a `v*` release.
Pushed to `git@github.com:xudingjun3131/mouseshare.git` (origin already configured). Debug build links on macOS.

Gotchas fixed: `eframe::run_native` closure must return `Result<Box<dyn App>, Box<dyn Error+Send+Sync>>` and its error is NOT Send+Sync, so don't use `?` into `anyhow::Result` — handle with `if let Err`. `rdev::Button::Unknown` is `u8` (not u32).

## CI debugging saga (resolved)
- Linux: kept failing because the `apt-get install` step aborted the whole job (exit 100) so `cargo build` never ran. Fix: install each X11 dev package individually in a loop with `|| echo APT_FAIL` so one missing pkg can't abort; also switched eframe to X11-only (`default-features=false, features=[accesskit,default_fonts,glow,x11]`) to drop wayland/EGL link deps. Green from run #6.
- Windows: `choco install innosetup` was flaky (downloads compiler from files.jrsoftware.org; worked runs #1-4, failed #5-6). Fix: retry loop up to 3x + call ISCC via explicit path `$env:ProgramFiles(x86)\Inno Setup 6\ISCC.exe` (avoids choco PATH-shim not refreshing in same shell), and ALWAYS `Compress-Archive` the .exe so a Windows artifact ships even if installer download hiccups. Green from run #7.
- Final: Build step uses `shell: bash` + `set -o pipefail` so a real compile error is fatal; `upload-artifact` uses `if: always()`; debug step PATCHes Issue #1 (no new-issue spam).
- **All 3 platforms green at run #7 (54e492c); pushed tag `v0.1.0` -> run #8 published Release v0.1.0 with .deb/.tar.gz/.dmg/MouseShare-Setup.exe/.zip.** CI goal achieved.

## Feature: unlimited clients + copy (commit d4f0ade, release v0.2.0)
User asked: "带复制功能，不限制客户端数量".
- 不限制客户端数量: network layer already uses unbounded `HashMap` + `listener.incoming()` loop, but a connected secondary was only usable if a matching `Screen` existed in the layout. Fix: on `Message::Hello` (primary only) call `Layout::ensure_screen(name, w, h)` to auto-register a screen (placed right of rightmost) — so any number of secondaries "just work" with no manual add. `layout.rs` got `ensure_screen` + `duplicate_screen`.
- 复制功能 (two parts): (1) GUI screen list in the SidePanel with per-screen 「复制」(clone, name `-copyN`, offset right) and 「删除」(keep >=1) buttons, plus manual "+ 右侧添加屏幕"; (2) Primary panel 「复制连接地址」button → `clipboard::set_clipboard(&config.server_addr)` with a transient status line.
- `cargo check` green locally; run #9 (33752825813) all 3 OS green; tagged v0.2.0 → run #10 published Release v0.2.0 with all 7 assets.
- Note: `cargo` is NOT on default PATH here; source `$HOME/.cargo/env` or use `~/.cargo/bin/cargo` (rustup 1.98.0).
- Note: GitHub Actions job logs need admin (403 via API); the commit `check-runs` API (`/commits/{sha}/check-runs`) IS readable anonymously and is the reliable way to verify a run's per-OS status. The workflow runs list page is heavily cached.
