参照：**Lan Mouse** (feschber/lan-mouse, Rust, 核心仅 3466 行) + **Input Leap** (C++, Barrier fork)。

### 三个根本性设计错误（我们 vs 行业共识）
1. **捕获必须是 grab，不是 observe**（最致命）。
   - rdev::listen 是**观察者**：事件照常进本地系统，拦不下来。所以本地机器仍响应所有输入，warp 光标会产生 echo/跳变，被 OS clamp 后又没 delta → 只能靠 treadmill 打补丁，方向从根上就错了。
   - Lan Mouse/Input Leap 全部用真正的 grab：
     | 平台 | API | 阻止事件的方式 |
     |---|---|---|
     | macOS | `CGEventTap`(Session, HeadInsertEventTap) | `CallbackResult::Drop` + `cg_ev.set_type(CGEventType::Null)` |
     | Windows | `SetWindowsHookExW(WH_MOUSE_LL/WH_KEYBOARD_LL)` | 回调返回 `LRESULT(1)` |
     | Linux Wayland | libei / layer-shell | 协议层 grab |
     | Linux X11 | XGrabPointer / XI2 | grab |
2. **协议应传相对 delta，不是绝对坐标**。
   - Lan Mouse `PointerEvent` 只有 `Motion{time, dx, dy}`，**完全没有绝对坐标**。
   - Input Leap：`onMouseMovePrimary(x,y)` 用绝对（真实光标在本地），`onMouseMoveSecondary(dx,dy)` 用相对。
   - 传绝对坐标要求两端屏幕几何/缩放完全同步，多屏+缩放下必然漂移、跳变。
3. **边缘判定要用"预测"，不能等光标被 clamp**。
   - Lan Mouse `crossed()`: 用 `location + MOUSE_EVENT_DELTA_X/Y` 判断越界 —— 在光标**到达**边界的那一帧就判定，此时事件流还在。
   - Input Leap: `zoneSize` 边缘区 → 把坐标**向外偏移 zoneSize** 得到虚拟越界坐标 → `mapToNeighbor()` 查哪块屏包含它 → `isSwitchOkay()` 综合判定（含 two-tap 防误触）。
   - 捕获期间：光标 hidden + warp 回边缘内侧 1px（enter_position），每次移动都 reset；因事件被 Drop，warp 无副作用。

### 正确架构（重写目标）
虚拟光标可越界 → 用扩展坐标查邻居屏 → switchScreen → 真实光标 clamp 在本地边缘 + 隐藏 → 之后只发 delta → 对端累加。回来时由对端在自己区域外发 `Leave`。
状态机极简：`WaitingForAck → Sending → Leave`（Lan Mouse）。释放时合成所有按下键的 key-up + 清零 modifiers，否则对端会残留"幽灵修饰键"。

### 保留 / 重写边界
保留：网络层(TCP)、剪贴板、配置、egui UI（布局拖拽/主题刚重做过）。
重写：input 捕获(改原生 grab)、注入、协议(改 delta)、跨屏状态机。
删除：treadmill、remote_move、park_anchor、edge-rest poller 等所有为弥补 observer 缺陷而生的补丁（delta.rs 已删）。
预估：新增 ~900 行（macOS ~200 / Windows ~250 / Linux X11 ~250 / 状态机协议 ~200），删 ~800 行补丁。
