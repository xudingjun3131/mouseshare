## 跨平台打包失败修复（v0.3.33）

用户报告 Windows + Ubuntu 打包失败，macOS 成功。根因：`src/capture.rs` 顶层**无条件** `use core_foundation` / `use core_graphics`，但这两 crate 只在 `[target.'cfg(target_os = "macos")'.dependencies]` 声明，非 macOS 编译时未链接 → E0433 `cannot find crate`。那个 `rdev` "mutable reference to mutable static" 只是 warning（rdev 自身代码，不致命）。

### 修复
- 把 `core_foundation`/`core_graphics` 的 `use` 改成 `#[cfg(target_os = "macos")]`（其余 mac-only 代码 input.rs::cursor_position、main.rs::detect_primary_layout 早已在 macos cfg 块内，已确认）。
- 验证：`cargo check` 对 `x86_64-pc-windows-gnu` 与 `x86_64-unknown-linux-gnu` 均 **Finished / 0 E0433**；macOS 原生 build + 12 测试全过。
- 本地交叉 check 的坑：Mac 上缺 `pkg-config` 二进制 + X11 头文件，`x11` 依赖 build script 会 panic。用 `PKG_CONFIG_PATH=/tmp/fakepkg PKG_CONFIG_ALLOW_CROSS=1`（造一批假 .pc，x11 版本≥1.4.99.1）越过——这与代码无关，真实 Ubuntu CI 自带 `libx11-dev` 不会触发。

### 教训
- **打 tag 后必须 `git push --tags`**（之前 v0.3.31/v0.3.32 只推了本地，用户 GitHub 看不到；本次 v0.3.33 已 `git push origin main --tags` 并远程确认）。

## v0.3.36 —— 修复"中英文切换按钮被挡住"

用户反馈 v0.3.35 后语言切换按钮被遮住。根因：`status_pill` 用 `ui.allocate_rect(Rect::from_min_size(ui.cursor().min, ...))` **手动定位矩形**，而工具栏右侧区是 `right_to_left` 布局 —— `allocate_rect` 不遵循布局方向，且宽度用 `glyph_width('M') × 字符数` 估算（中文严重失真）。它又在语言按钮**之后**绘制（后绘制=上层），所以直接盖住了语言按钮。旧版用的是标准 `ui.label`，故无此问题。

### 修复
- `status_pill` 改为**纯布局驱动**（`egui::Frame` + `inner_margin` + 内层 `horizontal` + 两个 `label`），不用任何手动矩形；状态点改用 `allocate_exact_size` + `circle_filled` 画真圆（不依赖 "●" 字形）。宽度自动适配任意语言。
- `secondary_btn` 同步加固：`allocate_rect` → `allocate_exact_size`（遵循布局方向 + 正确推进光标，堆叠按钮不会互相重叠）。

### 教训（egui 自定义控件）
- **在 RTL / 嵌套布局里绝不要用手动 `allocate_rect` + `ui.cursor()`** —— 它忽略布局方向，会画到相邻控件上面。自定义控件一律用 `allocate_exact_size`（或直接用标准 widget + Frame），让 egui 负责排版。
- 需要"左品牌 + 右操作"时，`ui.horizontal(|ui| { 左内容; ui.with_layout(right_to_left, |ui| {...}) })` 是标准且可用的写法，嵌套 RTL 会拿到剩余宽度。
