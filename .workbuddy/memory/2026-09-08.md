## v0.3.36 —— 修复"中英文切换按钮被挡住"

用户反馈 v0.3.35 后语言切换按钮被遮住。根因：`status_pill` 用 `ui.allocate_rect(Rect::from_min_size(ui.cursor().min, ...))` **手动定位矩形**，而工具栏右侧区是 `right_to_left` 布局 —— `allocate_rect` 不遵循布局方向，且宽度用 `glyph_width('M') × 字符数` 估算（中文严重失真）。它又在语言按钮**之后**绘制（后绘制=上层），所以直接盖住了语言按钮。旧版用的是标准 `ui.label`，故无此问题。

### 修复
- `status_pill` 改为**纯布局驱动**（`egui::Frame` + `inner_margin` + 内层 `horizontal` + 两个 `label`），不用任何手动矩形；状态点改用 `allocate_exact_size` + `circle_filled` 画真圆（不依赖 "●" 字形）。宽度自动适配任意语言。
- `secondary_btn` 同步加固：`allocate_rect` → `allocate_exact_size`（遵循布局方向 + 正确推进光标，堆叠按钮不会互相重叠）。

### 教训（egui 自定义控件）
- **在 RTL / 嵌套布局里绝不要用手动 `allocate_rect` + `ui.cursor()`** —— 它忽略布局方向，会画到相邻控件上面。自定义控件一律用 `allocate_exact_size`（或直接用标准 widget + Frame），让 egui 负责排版。
- 需要"左品牌 + 右操作"时，`ui.horizontal(|ui| { 左内容; ui.with_layout(right_to_left, |ui| {...}) })` 是标准且可用的写法，嵌套 RTL 会拿到剩余宽度。

### 排查结论
- **字体加载本身没问题**：macOS 读 `/System/Library/Fonts/SFNS.ttf`（确认存在，7.9MB）作为 Proportional 首选，Noto Sans SC 作 CJK 回退；`setup_fonts`/`setup_style` 在 `main.rs:378-379` 正确调用，全仓库无其它 `set_style`/`set_visuals` 覆盖。

- **"没变化"最可能的原因**：v0.3.35 起界面已有**明显可见**变化（角色切换由单选圆点变成 NSSegmentedControl、macOS 交通灯浮在工具栏上、SF Pro 字体、新配色分层）。用户说完全没变化 → 大概率跑的是旧构建（没 `git pull` / 没重新 `cargo run` / 用的是旧 tag 打的 release 包）。**需用户确认并截图**才能继续。

### 工具教训（重要，本会话多次踩坑）
- **macOS 自带 grep 是 BSD grep，BRE 不支持 `\|` 交替**。`grep -n "a\|b"` 会**静默返回 0 匹配**，极易误判成"代码里根本没有这个符号"，本会话因此多次得出错误结论并浪费排查轮次。
- 正确写法：`grep -E "a|b"` 或 `grep -e a -e b`，或直接用 ripgrep 系的 Grep 工具（它对 `|` 处理正确）。

- **列表**：`peer_row`（36px 图标块 + 名称 + monospace 元数据 + 右侧状态/操作胶囊），替代原来的 `[复制 2 删除]` 挤一行。

### egui 踩坑（本轮新增）
- **不要用 `ui.cursor()` 定位 painter 文本**：空布局下 cursor 高度是 0，文本位置会随 egui 内部状态漂移。一律 `allocate_exact_size` 拿显式 rect 再画。
- **中英混排换行**：`text.split(' ')` 对中文永不换行（无空格）。`wrap_lines` 里按 `(c as u32) > 0x2E80` 判断 CJK，逐字断行；Latin 按空格断。
- **自定义可点击卡片**：整卡用一次 `allocate_exact_size(..., Sense::click())`，其余全用 painter 画 —— 不要在内层塞 Label widget，会和点击区抢事件。
- **`egui::Margin` 字段是 i8**（≤127），40 这种数可以但要注意别超。
- `Ui::set_clip_rect(rect)` 可安全用于把画布内容限制在分配区内。

### 本地打包（可复用命令）
`gh` CLI 未登录（`gh auth login` 未执行），**无法用 `gh run list` 查 CI**；改用 `WebFetch https://github.com/<owner>/<repo>/actions` 和 run 详情页查看状态/产物（public 仓库可读），或直接看 `releases/tag/<ver>` 页面的 Assets。
本地出 dmg（与 CI build.yml 的 macOS 步骤一致，约 28s release 构建）：
```
cargo build --release
mkdir -p MouseShare.app/Contents/{MacOS,Resources}
cp target/release/mouseshare MouseShare.app/Contents/MacOS/
cp resources/AppIcon.icns MouseShare.app/Contents/Resources/
# Info.plist: CFBundleName/DisplayName/Identifier(com.mouseshare.app)/Version/
#             ShortVersionString/Executable(mouseshare)/IconFile(AppIcon)/
#             PackageType(APPL)/LSMinimumSystemVersion(10.13)
codesign --force --deep --sign - MouseShare.app     # ad-hoc 签名，右键可越过 Gatekeeper
mkdir dmgstage && cp -R MouseShare.app dmgstage/ && ln -s /Applications dmgstage/Applications
hdiutil create -volname MouseShare -srcfolder dmgstage -ov -format UDZO mouseshare-mac-local.dmg
```
- `.gitignore` 已忽略 `MouseShare.app/`、`*.dmg`、`*.zip`、`*.deb`；本轮补 `dmgstage/`。
- 本地 dmg 打在 `mouseshare-mac-local.dmg`（11.3MB），签名 `codesign -v` 校验通过。
